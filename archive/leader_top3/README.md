# archive/leader_top3/ — index to the top-3 qr_v2 submissions

The qr_v2 submissions were published on the
[leaderboard](https://www.gpumode.com/leaderboard/774) after the 2026-06-30 deadline. This file is my
own **index and reading notes** for the top three, written so the analysis in
`docs/HOW_LEADERS_ARE_FAST.md` (§6 references the kernel names below) has a provenance trail.
Ranking: **A = 1st, B = 2nd, C = 3rd.**

## No source is vendored here — by design
This directory deliberately contains **no third-party code**. Publicly viewable is not the same as
licensed for redistribution, and the submissions are large (C alone inlines the full CUTLASS/CuTe
PTX-wrapper headers). Read them at the source above; what follows is a structural index, in my words.

Everything below is **my reading of published code**. The architectural claims are inferences about
what the code does, not claims about anyone's intent.

## A.py — rank 1 — pure Triton, algorithm-first
- Header: `#!POPCORN leaderboard qr_v2` / `"""Compile-slim B200 QR hybrid."""`. NO load_inline, NO CUDA, NO graphs.
- Routing (`custom_kernel`): n∈{32,176,352}→`_small_qr_v2`; n=512→`_safe512_qr_v2`; n=1024→`_s9_n1024_n1024_qr_v2`; n∈{2048,4096}→`_n2048_qr_v2`.
- Panel = **CholeskyQR reconstruction** (Gram→blocked Cholesky→reconstruct compact-WY): `_safe512_cholesky_factor_32_launch`, `_s9_n512_n2048_chol32_factor_kernel`, `_n2048_chol32_factor_kernel` (Newton-refined inverse).
- **Per-matrix precision classifier**: `_s9_n512_n512_classify_precision_kernel`, `_safe512_classify_precision_kernel` (dense/band/rankdef/clustered/near-collinear/near-rank flags).
- fp16 working buffer + trailing; mxfp8 two-term `_v10_mxfp8_two_term_dot`; recursive WY 32→64→128 `_s9_n1024_n1024_assemble_recursive_t64_kernel`; structural truncation `zero_tail`/`nearrank`.

## B.py — rank 2 — CUDA + cublasLt, panel-first (exact Householder)
- Uses `load_inline(CPP_SRC, CUDA_SRC)`.
- Panel kept EXACT Householder but made physically fast:
  - `register_panel_kernel<ROWS,COLS,N>` — register-file, warp-owns-columns, `mbarrier`+`elect.sync`.
  - `register_2sm_panel_kernel` — **2-SM cluster** (`__cluster_dims__(2,1,1)` + `cp.async.bulk` TMA + `mapa.shared::cluster` + `st.async.shared::cluster`).
  - `gmem_panel_kernel` — **multi-CTA cooperative panel** via `st.release.gpu`/`ld.acquire` atomic flags.
- Trailing: `compact_wy_apply_transpose` via cublasLt per-member compute-type — `tf32_baddbmm_out` / **`bf16x9_baddbmm_out`** (`CUBLAS_COMPUTE_32F_EMULATED_16BFX9`) / `fp16_baddbmm_out`; owned T `build_t128_diag`/`build_t96_diag`.
- Python: `smem_blocked_qr`, `scheduled_global_qr`, `SHORT_BLOCK_WIDTHS`, `GLOBAL_QR_SCHEDULES`.

## C.py — rank 3 — raw CUDA + inlined CUTLASS/CuTe PTX, engine-first
- Header: `# Generated by kernels/qr/submission_codegen.py`. `load_inline` of `_CUDA_SRC + _GRAMDC_CUDA + _CQRGEMM_CUDA + _CQR_CUDA + _N32_CUDA + _COLNORM_SRC`.
- **Inlines the CUTLASS/CuTe PTX-wrapper headers**: `ptx_tcgen05.cuh`, `mma_desc.cuh`, `ptx_tma.cuh`, `ptx_mbarrier.cuh`, `ptx_sync.cuh`, `tensor_map.h`, `swizzle.h` (`ptx::` / `tmap::`).
- **Warp-spec persistent tcgen05 engine** owning every GEMM: `gramdc_kernel` (dual-consumer SYRK, producer-TMA + 2 consumer warpgroups + mbarrier ring + TMEM double-buffer + `tcgen05.commit`), `swaptrail`/`usolve_tc`/`extinv_fused`.
  - NOTE: C's own comments admit these are **sub-cuBLAS** (`SUB-CUBLAS GRAPH-BLOCK 0.84-0.96x`), kept only to make the CQR call graph-capturable.
- **Launch-gap elimination**: PDL (`launch_pdl` / `griddepcontrol` / cudaLaunchAttribute id 6) + **explicit-node CUDA graph** (`cudaGraphAddKernelNode` / `og_graph_build[_codisp]` / `og_graph_launch` — uses "graph" freely; comment "NO capture API used (grep -ic on the banned token == 0)" ⇒ only "stream" is banned).
- **In-grid co-dispatch megakernels**: `k_panel_codisp` (panel(k+1) ∥ trailing-TAIL(k)), `k_fused_diag_codisp` (chol-diag ∥ lu-diag ∥ chol-Schur-tail), all blockIdx-partitioned in ONE grid.
- **Block-pipeline**: left-looking LU + leading inverse, `k_fused_diag` (chol(k+1) ∥ lu(k)).
- Algorithm: CQR-BDGHK (Gram→Chol→R+Aeq→LU→reconstruct→assemble) for n≥2048 dense; blocked-WY Householder (`larfb_qr_run*`, owned bf16x3 `qr_cpref`) for n≤1024.

## The one-line takeaway
Ranking A>B>C says the deepest engineering (C's full tcgen05 engine) came LAST; the algorithmic
reformulation (CholeskyQR panel) + per-matrix precision routing + launch-gap elimination — all
expressible in plain Triton (A) — is where most of the ~3.3× lives.
