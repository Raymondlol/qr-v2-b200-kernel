## ⚠️ HARD CONSTRAINTS — violating any = rejected or disqualified
1. **NEVER write the substrings `stream` or `graph` ANYWHERE in a submission, including comments.** The submission checker does a naive static substring scan. `grep -niE "stream|graph" submission.py` MUST be empty before every submit. (No CUDA streams, no CUDA graphs, no cooperative-launch either — but the words alone also trip it.)
2. **Trailing GEMM precision floor = ~22 mantissa bits (tf32x3; fp16x3 is the SAME accuracy AND ~the same SPEED — no win) for n≤512.** 1×TF32 FAILS n=512 **mixed at batch=640** (worst-of-640 sfr→19.7, m1.02, reseed-DQ). **CORRECTION (2026-06-26, branch `fp8-fp4-attack`, see [[qr-v2-solve-tf32-floor-artifact]] / docs/FP8_SESSION_PROGRESS.md): the documented "tf32x3 only ~2× margin" was a TF32-SOLVE artifact, NOT a trailing wall** — forcing `solve_triangular`→fp32 gives ~800× margin at +~1% (a robustness option, `experiments/cand_fp16x3_solvefix.py` — note it's fp16x3-based; the same solve-fix on tf32x3 V5 is the deployable robustness variant). **FP16x3 = OFFICIAL WASH** (fp16 fp32-acc = tf32 rate; Modal +3.6% did not transfer). **fp8/fp4 = accuracy-viable (m10.8 @ 6 Ozaki dots) but NOT a speed win** (K-poor batched shapes negate fp8's 4×, dedicated tcgen05 cores verified used). n≥1024 may use 1×TF32. Panel reductions must stay FP32 (low-precision panel corrupts reflectors).
3. Output must be **flat compact-Householder** (one reflector v per column in strict-lower(H), R=triu(H), tau). `householder_product` reads only strict-lower(H)+tau.
4. **Shape-routing** to correct algorithms is allowed; **conditioning-based routing** to a numerically-invalid path is NOT. `recheck=True` every timed iter (no output caching).
