Candidate

experiments/v10_sub5_fused32_ib32_nw2.py

Change
------
V10's _use_geqrf(batch, n) sends n <= 64 to torch.geqrf, which makes the official
b20 n32 dense case pay a cuSOLVER path cost around 318-324us.

The candidate routes CUDA n <= 64, B > 16 through the existing one-shot Triton
fused QR kernel with IB=32, nw=2:

  if _HAS_TRITON and n <= 64 and B > 16:
      return _fused_qr(A, IB=32, nw=2)

All other cases remain on the existing V10 paths.

Read
----
This is a real routing win, not a fragile PTX/SASS micro-tune. It replaces a costly
small-n geqrf path with the already-correct one-shot fused QR kernel. The final
clean file got to 4.035ms in the Modal lab, so the immediate sub-5ms gate is met.

This does not explain or close the 1.3ms-class leaderboard gap. The CUTE
profiler/PTX/SASS pass in results/cute_v10_prof_asm_2026-06-28.txt showed that the
current CuTe M3d_NB8 path is 30x slower than V10 at B=20,n=128 despite lower regs
and no spills. The next load-bearing step for the 1.3ms route is still a real
tcgen05/TMEM TF32x3 far-apply, not more scalar warp scheduling polish.
